# Memory

Memory lives in the Obsidian vault at `~/HOME/wizzard/Holocron/memory/`; paths below are relative to the vault. Memory is a budget, not an archive. `memory/MEMORY.md` is read at the start of every session, so every line in it is paid for forever. Anything most sessions do not need belongs in `memory/long/`, opened only when the task needs it.

| Path | Loaded | Size |
|---|---|---|
| `memory/MEMORY.md` | every session | <= 400 lines (~4k tokens), hard |
| `memory/wiki/overview.md` | every session | 15-20 lines |
| `memory/wiki/*.md` | on demand | unlimited |
| `memory/long/*.md` | on demand | unlimited |
| `memory/journal/YYYY-MM-DD.md` | never | append-only, cleared on consolidation |

## Recall

1. Read `memory/MEMORY.md`, then `memory/wiki/overview.md`. Nothing else by default.
2. If the Long-term section lists a note that matches the current task, read that one file. Not the folder.
3. Still thin: search the `wiki` library, then `self`, then `notes` (skill `notes`), in both languages. A page written in the last 30 minutes is not indexed yet, read it by path.
4. Else `grep -ril "<term>" memory/` and open the single hit; then grep the journal for dates or names.
5. Ask the user instead of inventing history.

Use what you recall. Do not dump memory back at the user as a summary.

## Wiki

`memory/wiki/` is written by the agent only: synthesis of several sources, contradictions, principles. A digest of one source stays a normal note. The page format, ingest (extend a page instead of adding a near duplicate), query and lint live in the `wiki` skill. `memory/wiki/index.md` is generated by `memory/tools/memory-index`, never edited by hand, never loaded as context.

## Auto-capture

Write without being asked and without asking permission. Append one line to `memory/journal/YYYY-MM-DD.md` (create the file from the header below when the day changes) as soon as the fact appears, not at the end.

Write when:

- a decision is made and the reason will matter later.
- the user corrects you, or states how they want work done.
- an environment fact cost you a detour: a path, a flag, a command that fails, a service that is not there.
- a task ends and its outcome changes what happens next.
- you made a mistake worth not repeating.

Do not write: progress narration, what a file contains, git history, the next step of the current task, anything `AGENTS.md` already states, anything that is only true for this one task.

Gate before writing: at least two must be true.

1. Still true in a month?
2. Re-learning it would cost time or a mistake?
3. It changes how you work, not only what this task needs?

Journal noise is not free: every line makes the next consolidation heavier. One fact per line, <= ~120 characters, no prose, no code blocks. Do not announce writes unless the user asked.

Header for a new journal file:

```
# Journal YYYY-MM-DD

Raw log. Never read at session start. Compacted into MEMORY.md, then cleared.
```

## Consolidate

Triggered by "сохрани сессию", "уплотни память", the end of a substantive session, or the journal passing ~60 lines.

1. Read `MEMORY.md` and the journal.
2. Rewrite `MEMORY.md` in place. A rewrite, not an append: merge duplicates, drop finished next-actions, keep the newest date on a fact that changed.
3. Detail that is rarely needed: move it to `memory/long/<topic>.md`, then leave one line in the Long-term section saying what it holds and when to open it.
4. Empty the journal, keep its header.
5. `wc -l memory/MEMORY.md` must be <= 400 and the Long-term section <= 40 lines. Over budget: evict before writing.
6. `git add memory && git commit -m "memory: <what changed>"`.

## Eviction order

When over budget, drop in this order:

1. Next-actions already done.
2. Decisions that no longer affect anything, oldest first.
3. Duplicates and near-duplicates, keep one.
4. Detail that can live in `long/`: move it, keep the index line.
5. Facts nobody acted on for ~90 days: drop, or demote to `long/`.

## Shape of MEMORY.md

```
# Memory

Last consolidated: YYYY-MM-DD. Budget: 400 lines.

## Who
## State
## Preferences
## Decisions
## Gotchas
## Next
## Long-term (memory/long/, open on demand)
```

## Rules

- One fact per line, <= ~120 characters. Dates as `YYYY-MM-DD`.
- Conflicting facts: newest wins, keep the old one only if its reason still matters.
- Never store secrets, tokens, keys, or file contents from `.env` and sops.
- Never restate what `AGENTS.md` says. Memory is what the rules do not cover.
- Same language as the source, no introductions, no summaries.
